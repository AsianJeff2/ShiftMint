# ShiftMint codebase audit

This report covers the full cloned `AsianJeff266/ShiftMint` source at baseline commit **`f43a2ed`**, and the modernization snapshot on `fix/modernize-and-pos-readiness`. The historical partial source found outside this repository is not the audit baseline. File locations below refer to the current checkout unless marked baseline; line numbers can move as final repairs land.

The first independent Claude review rejected an earlier candidate and identified further repairs. The repaired snapshot passed local integrated verification and compiled acceptance described below. The user authorized private transfer after checks and independent review. The final release record must identify the immutable review, resulting commit and transfer outcome. No hosted deployment has been observed.

## Inventory and supported architecture

| Area | Current source and responsibility |
| --- | --- |
| Renderer | `main.tsx`, `App.tsx`, `pages/`, `components/`: React, TypeScript, HashRouter, and Vite; dashboard, employees, shifts, tips, payroll estimates, settings, and error detection. |
| Browser state | `contexts/LocalAuthContext.tsx`, `contexts/DataContext.tsx`, `hooks/`, `lib/api-client.ts`: authenticated API requests, normalized response data, and shared refresh/export behavior. |
| API | `electron/backend/server.ts`, `routes/`, `middleware/`: Express authentication, business scope, role permissions, payroll/tip rules, exports, maintenance, and POS connection controls. |
| Persistence | `prisma/schema.prisma`, `prisma/migrations/`, `electron/backend/database.ts`, `migrations.ts`: Prisma and SQLite with guarded startup migrations, consistent snapshots, and validated restore. |
| Desktop | `electron/main/`, `electron/preload/`: canonical Electron entry, persisted workspace keys, trusted IPC, renderer policy, and backend/database lifecycle. |
| POS | `lib/pos/`, `electron/backend/services/pos-connections.ts`, `routes/pos.ts`, `components/settings/IntegrationsSettings.tsx`: encrypted server credentials and read-only Square/Toast previews. |
| Shared helpers | `lib/security/`, `lib/transformers/`, `lib/export/`, `types/`: encryption, authorization, DTO/date conversion, and safe file export. |
| Historical helper layers | Unused divergent domain/repository graphs and trivial tests were archived after active consumer searches. Their old test counts are excluded from the release suite. Residual compatibility helpers are not substitutes for the mounted API; the Supabase compatibility stub is not a Supabase backend. |
| Build and delivery | Root package/lockfile, separate frontend/server/Electron TypeScript configs, Vite/Vitest `.mts` configs, GitHub verification workflow, `Dockerfile`, and `render.yaml`. Node 24 is the supported toolchain. |
| Regression tests | Existing helper tests plus new `tests/browser`, `tests/database`, `tests/desktop`, backend security/lifecycle, export, and POS tests. |
| Archive | `archive/`: duplicated portable/working apps, independent launchers, ad hoc database/source-rewriting scripts, obsolete reports, and unused frontend forks. Excluded from supported compilation, tests, and container images. |

The active backend is **Express/Prisma/SQLite**, not Supabase. The hosted runtime serves the renderer and API from one origin. The desktop runtime keeps a local service and database. One process owns a SQLite workspace; hosted startup and restore reject multiple businesses. There is no managed Postgres migration or multi-instance architecture in this release.

At baseline, production compilation failed despite **281 passing legacy tests**. Those tests mainly established helper behavior, not the active HTTP routes, wire contracts, database upgrades, or desktop packaging. Duplicated scripts and earlier completion reports also overstated readiness. They were inspected as historical evidence, not accepted as verification.

## Independent review repairs

Round 2 found a Linux-only verification assertion and period-export timestamps that violated the API's calendar-date contract. The platform tests now cover Windows, macOS and Linux path branches, and both payroll export callers normalize real HTTP period timestamps to date-only markers. Further repairs refuse invalid runtime modes, limit the migration subprocess environment and disable Prisma checkpoint telemetry, preserve clock-tab state during refresh, retain actionable server errors, archive unused legacy UI and helpers, refresh rates when reassigning shifts, require explicit timezone offsets on shift/tip writes, use venue calendar dates for CSV shifts, and reject unresolved earlier-workweek context before payroll closure. Focused regressions reproduced the defects; the integrated verification and compiled acceptance above cover this revised source. Required independent review binds the immutable final candidate separately.

The `deepmerge-ts` 8.0.2 override patches the vulnerable transitive version pinned by Prisma 6.19.3. This crosses Prisma's declared major-version constraint. Generation and real migration/restore checks exercise the current combination; retain a compatibility check on every Prisma or override upgrade. Desktop `RunAsNode` remains enabled because the packaged migration CLI uses the Electron executable as its Node runtime. Disabling that fuse requires a redesigned child runtime and new packaged acceptance. The unpacked desktop dependencies and unsigned executable remain a local tampering risk; the current package check does not establish installer/signing acceptance.

The first independent review returned changes-required. Its backend blocker exposed Zod 4 defaults leaking into partial updates: omitted employee, shift and tip fields could be reset. Default-free update schemas now preserve existing values, with HTTP regressions for terminated employees, break/review status, tip type and provenance. Browser/API repairs also retain stored shift rates, actual tip timestamps and linked IDs through create, list and update contracts.

The desktop now requires a per-launch API capability delivered through trusted IPC, in addition to ordinary session and first-owner bootstrap authorization. Build cleanup resolves and guards only the intended output directories. Unsupported UI actions and divergent unused implementation graphs were removed from the supported runtime. A reproduced real Radix Select initialization callback cleared a linked tip during a notes-only edit; the renderer now ignores same-value employee initialization and preserves the relationship. Regression results for those repairs are included in the integrated suite above. Further regressions corrected imported-type Select hydration, grouped shift type casing, missing CSV enum variants, string booleans, malformed currency, invented timestamps/hire dates, quote handling and zero/partial import messages. Confirmed rejections retain row details; uncertain outcomes clear the pending batch and require inspecting saved records before a new upload. Compiled imports and metadata-preserving edits passed after repair.
